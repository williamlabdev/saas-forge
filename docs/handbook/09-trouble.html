9. 遇到問題時

現象大多是這個原因
schema/plan 回 403你的角色是 viewer。plan 需要 content:schema:plan,viewer 沒有——連看影響都不行。
GET …/proposals 回 403,但 …/proposals/mine 可以你是 editor。這是正常的——審核佇列與「自己送出的提案」是兩條分開授權的端點(見 6.4)。
提案送出後沒人理,後來變成 expired七天沒人回答就自動失效。重新送一次即可,結構沒有被動到。
核准了但不知道提案人有沒有看到目前不會主動通知,提案人要自己查 …/proposals/mine。
Agent 回 403三種可能:content type 不在 allowed_types、憑證的 tenant_role 不足、或動作本身就不開放給 agent(例如發佈、刪欄位)。
Agent 回 429撞到每支 agent 的速率限制。調 AGENT_RATE_LIMIT,或讓 agent 放慢。重發憑證沒有用,限制是綁 agent 名稱的。
Agent 憑證不見了token 只在發放當下顯示一次。撤銷舊的,重發一張。
API 全部回 401 / 被 gateway 擋少帶 X-Gateway-Secret,或值跟部署設定不符。
本機資料亂了想重來docker compose down -v && docker compose up --build -d && ./scripts/seed-demo.sh
前台讀不到剛寫好的內容它還是 draft。delivery edge 只給已發佈的內容。

9.1 上線前的檢查清單

  • AUTHZ_MODE 設成 rbac 或 opa(不能是 allow)
  • AUTH_DEV_HEADERS=false
  • 換掉 docker-compose.yml 裡所有 *_HEX 測試密鑰
  • 設定 GATEWAY_SECRET,並確認 domain API 沒有直接暴露在公開網路上
  • 視流量設定 AGENT_RATE_LIMIT(預設 0 代表不限制)
  • 盤點一次已發放的 agent 憑證,撤銷不再使用的
