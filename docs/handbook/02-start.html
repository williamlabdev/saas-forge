2. 開始使用

2.1 啟動(本機)

cp .env.example .env
docker compose up --build -d     # Postgres + Domain API + BFF + delivery + MinIO
./scripts/seed-demo.sh           # 建立示範帳號與範例資料

console 不在這個 repo 裡。它是一個獨立的 React + Vite 專案,沒有開源(見第 4 章)。手上有它的人另開一個終端機跑 cd ../saas-platform-console && pnpm dev;沒有的人,下面除了第一列 以外的服務都照樣起得來,操作走 API 或 GraphQL Playground。

服務位址用途
Admin console
(另一個 repo,未開源)		localhost:5173人用的操作介面
Domain REST APIlocalhost:8080API 與 agent 的入口(/health 可探活)
GraphQL BFFlocalhost:4000console 的聚合層(/playground 僅開發用)
Delivery edgelocalhost:4100前台讀取已發佈內容
Postgreslocalhost:5433資料庫
MinIOlocalhost:9000 / 9001檔案欄位的物件儲存

2.2 登入

系統沒有預設帳號。seed-demo.sh 會替你建一個並印出帳密,預設是:

Emaildemo@demo.io
PasswordDemoPass123

要換掉:DEMO_EMAIL=you@x.io DEMO_PASSWORD=Secret123 ./scripts/seed-demo.sh

自己註冊也可以——對 POST /api/v1/users 送出 email / username / password 即可。

部署前一定要改掉的兩個開發預設 AUTHZ_MODE=allow 與 AUTH_DEV_HEADERS=true 會讓 API 對所有請求放行。上線前設成 AUTHZ_MODE=rbac(或 opa)且 AUTH_DEV_HEADERS=false,並換掉 docker-compose.yml 裡的 *_HEX 測試密鑰。另外,domain API 不該直接對外網開放,它預期坐在 BFF 或可信任的 gateway 後面。

2.3 重置

docker compose down -v          # 連資料一起清掉,重跑 migration
docker compose up --build -d
./scripts/seed-demo.sh
