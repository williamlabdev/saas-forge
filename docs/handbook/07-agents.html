7. 讓 AI agent 使用這套 CMS

Agent 不是拿你的帳號登入。它拿一張單獨簽發、範圍寫死、可以隨時撤銷的憑證,而且它能做的事永遠是你能做的事的子集。

7.1 發一張憑證

對 POST /api/v1/auth/agent-tokens 送出三件事(owner / admin 才有這個權限):

欄位意思
agent_id你替這支 agent 取的名字。稽核紀錄與速率限制都用它。
allowed_types白名單,必填且不可為空。沒列進來的 content type,這支 agent 完全碰不到。
tenant_role這支 agent 在租戶裡的角色。決定它是唯讀、能寫、還是能發佈。
token 只會出現一次明文只在這一次的回應主體裡。系統不保存明文,之後 GET /auth/agent-tokens 只列得出發放紀錄,列不出 token 本身。弄丟就只能撤銷後重發。
你發不出比自己更大的權限owner 能發 admin / editor / viewer;admin 只能發 editor / viewer;editor 與 viewer 一張都發不了。

7.2 撤銷

DELETE /api/v1/auth/agent-tokens/{id},{id} 取自 GET /auth/agent-tokens 的列表。撤銷立即生效——憑證裡帶著一個指向發放紀錄的識別碼,那筆紀錄被撤銷、過期或不存在,請求就會被拒。不需要等 token 自然到期。

7.3 呼叫方式

curl http://localhost:8080/api/v1/content/entries?type=article \
  -H "Authorization: Bearer <agent token>" \
  -H "X-Gateway-Secret: <gateway secret>"

Agent 與人用的是同一組 API 與同一個 header 格式。差別全在憑證裡帶的範圍。

7.4 速率限制

每支 agent 各自計算,額度不互相排擠(用 租戶 + agent 名稱 當 key,不是用憑證流水號——所以重發一張新憑證不會繞過限制)。人類使用者不受這層限制。

AGENT_RATE_LIMIT每個時間窗允許幾次請求。預設 0 = 不啟用
AGENT_RATE_WINDOW_SEC時間窗長度,預設 60 秒

超過時回 HTTP 429,錯誤碼 AGENT_RATE_LIMITED。

7.5 用 MCP 接(給 Claude 這類助理)

倉庫附了一個 MCP server(apps/cmsmcp),把 CMS 包成 AI 助理可以直接呼叫的工具:

工具做什麼
cms_describe列出這張憑證看得到的所有 content type、欄位、權限與可用的篩選運算子。agent 該先呼叫這個,而不是靠猜。
cms_list_entries查詢 entry,支援篩選、排序、locale 與欄位投影
cms_get_entry取單筆,含完整內容、版本號與發佈狀態
cms_list_translations列出某筆內容的所有語言版本
cms_create_entry新建草稿。可帶冪等鍵,重試不會變成兩筆
cms_update_entry修改草稿。必須帶版本號,避免蓋掉別人的修改
cms_set_status下架已發佈的內容。不能拿來發佈
工具清單本身就是一道界線沒有 cms_publish,也沒有任何刪除欄位的工具。「把東西放上線」與「破壞結構」這兩件事,不在 agent 的工具箱裡——它連要求都提不出來,只能透過提案流程請人決定。

設定

# 本機 stdio 模式
DOMAIN_API_URL=http://localhost:8080
CMS_AGENT_TOKEN=<agent token>
GATEWAY_SECRET=<gateway secret>      # 選填
CMS_MCP_TIMEOUT_SECONDS=10           # 預設 10
CMS_MCP_DEFAULT_LIMIT=10             # 預設分頁大小
CMS_MCP_MAX_LIMIT=50                 # 分頁上限

要部署成共用服務就設 CMS_MCP_HTTP_ADDR(例如 :8081)。此時不可設 CMS_AGENT_TOKEN——每個呼叫自己帶 token,一個行程不會綁死一張憑證。
