3. 概念與角色

3.1 租戶(tenant)

每一份內容都屬於一個租戶,租戶之間完全隔離。你的身分不是全站唯一的——同一個帳號可以在 A 租戶是 owner、在 B 租戶是 viewer。切換租戶(POST /api/v1/auth/switch-tenant)換到的是另一張 token,你的權限跟著那張 token 換。

3.2 四種成員角色

角色能做的事
owner租戶內全部權限,包含刪除欄位這類破壞性的 schema 變更、審核提案、發放 agent 憑證。
admin與 owner 相同的日常權限。差別在能邀請/發放的對象範圍較窄(見下)。
editor內容的建立、修改、刪除、發佈;可以新增欄位這類可逆的 schema 變更;可以提案破壞性變更,但不能自己套用。
viewer唯讀。看得到內容,看不到發佈佇列、活動紀錄與提案佇列。
邀請與發憑證的上限owner 可以邀請 admin / editor / viewer,admin 只能往下發 editor / viewer。editor 與 viewer 不能發放任何 agent 憑證。沒有人能邀請另一個 owner——owner 由租戶建立時決定。

3.3 一條分界線:誰能破壞既有內容

整套權限設計繞著一個問題轉:這個動作會不會讓已經存在的內容消失或壞掉?

動作誰可以為什麼
新增欄位、改標籤owner / admin / editor可逆,加了不會弄丟東西。
寫、發佈、下架內容owner / admin / editor能改內容的人就能決定它上不上線。
刪欄位、刪 type、改型別owner / admin會讓既有資料無法還原。這是唯一一條真正的界線。
看變更影響(plan)、送出提案owner / admin / editor兩者都不寫入任何內容;提案只是「請求」,不是權限。
審核/套用提案owner / admin與「刪欄位」是同一個權限,沒有第二道門。

3.4 Content type 與欄位

一個 content type 就是一種內容的結構定義(article、product…)。每個 type 帶一組欄位,支援的型別有:

string 單行文字text 多行文字richtext 富文本
number 數字boolean 是/否enum 選項
date 日期datetime 日期時間file 檔案
relation 關聯到其他 entry其中 string / number / enum / relation 可設為多值

Content type 上還可以掛三組角色限制,用來把某一種內容鎖得比租戶預設更緊:ReadRoles(誰讀得到)、WriteRoles(誰寫得了)、OwnOnlyRoles(這些角色只能動自己建立的 entry)。留空代表沿用租戶角色的預設。
