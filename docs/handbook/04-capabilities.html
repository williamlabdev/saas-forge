4. 能力地圖

系統的能力分成兩層:平台層決定有哪些 app 存在,應用層管理某一個 app 裡的內容。日常操作幾乎都在應用層。這一章把兩層的能力列成清單,每一項都對應一組你叫得到的端點——不論你是自己接前端、寫腳本,還是讓 agent 去做。

操作介面是你自己的選擇本專案是後端。開發時使用的 admin console 是一個獨立的 React + Vite 專案,沒有開源,目前也沒有開源計畫,而且它跟後端之間沒有任何私有協定——它走的就是這裡列出的公開介面。下面的表格因此有第三欄:那是 console 把該項能力放在哪個路徑,留著是因為它是這組能力的好名字,不是因為你需要那個 console。完整的端點簽章在第 8 章。

平台管理員不是租戶管理員平台層的 admin 身分不會自動讓你能動任何租戶的內容。要碰租戶資料,必須是那個租戶的成員。這是刻意的隔離,不是漏設。
權限差別發生在動作上,不在能力清單上能不能列出 content types,和能不能刪掉其中一個欄位,是兩個分開授權的動作(見 3.3)。所以「看得到入口、按下去才知道自己缺什麼」是預期行為,不是設計失誤——把整個能力藏起來,只會讓人不知道要去要什麼權限。開發用的 console 也照這個原則做:九個導覽項目對所有角色都看得到。
