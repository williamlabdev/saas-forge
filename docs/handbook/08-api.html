8. API 參考

所有內部 API 都掛在 /api/v1 之下,以 Authorization: Bearer <token> 認證。若部署有設定 gateway secret,除了 /health 之外每個請求都要帶 X-Gateway-Secret。

8.1 登入與憑證

路徑用途
POST/api/v1/auth/login登入取得 token
POST/api/v1/auth/refresh換新 token
POST/api/v1/auth/switch-tenant切換到另一個租戶的 token
POST/api/v1/auth/logout登出
POST/api/v1/auth/agent-tokens簽發 agent 憑證(owner / admin)
GET/api/v1/auth/agent-tokens列出已發放的憑證
DELETE/api/v1/auth/agent-tokens/{id}撤銷憑證

路徑需要的權限
GET/api/v1/content/typescontent:list

PATCH/api/v1/content/types/{name}/fields/{key}content:schema:amend
DELETE/api/v1/content/types/{name}/fields/{key}content:schema:write
POST/api/v1/content/types/{name}/fields/{key}/renamecontent:schema:write
DELETE/api/v1/content/types/{name}content:schema:write
GET/api/v1/content/schema/exportcontent:list
POST/api/v1/content/schema/plancontent:schema:plan

四個 content:schema:* 動詞的破壞性由低到高是 amend → plan → propose → write。只有 write 是 owner / admin 專屬。

8.6 對外取用已發佈內容(delivery edge)

前台站台走 :4100,路徑不含 /api 前綴,而且只讀得到已發佈的內容:

GET/v1/{tenant}/{type}/列出已發佈 entry
GET/v1/{tenant}/{type}/{id}取單筆已發佈 entry
GET/v1/{tenant}/media/{id}取已發佈的媒體

需要 delivery 憑證,與 console / agent 憑證是不同的東西。草稿永遠不會從這裡流出去。
